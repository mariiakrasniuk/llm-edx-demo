Three ideas. Then you’re ready.

01

The model learns patterns

A large language model (LLM) learns from many examples of text. Training adjusts its numerical settings so it gets better at predicting what comes next.

02

The transformer uses context

A transformer is the model’s design. It turns pieces of text into numbers and uses attention to mix information from the text it has seen.

03

A reply grows one piece at a time

The model predicts a small piece of text, adds it, and repeats. A likely continuation can still be wrong. Likelihood is not truth.

Your experiments use Qwen, a trained language model running on our server. ChatGPT is a chat application; Qwen is the model we can look inside here.

1. Words or pieces?

We read words. A model reads tokens: small pieces that can be a word, part of a word, a space, or punctuation. There is no rule that one word must equal one token.

Before you click: how many pieces will “Unbelievable!” become? Make a guess, then reveal the tokens. Try your name or a word in another language next.
Try:

First inspection loads the model and may take a little longer.

Keep this idea: a token is a building block of text, not necessarily a whole word.

How do pieces become numbers?

Each token has an ID. The model uses it to look up a list of learned numbers called a vector. You don’t need to interpret each number: together they give the model something it can calculate with.

You use the surrounding words to interpret “bank”. A language model also uses context: the text and instructions it receives. Let’s test whether changing the sentence changes its answer.

Compare each answer with your prediction. Different answers can result from different context without retraining. Unexpected answers are worth discussing: the model can make mistakes.

How does a transformer use those clues? Tokens become lists of numbers. Attention mixes information from available tokens, and further calculations update those lists over multiple rounds. Those updated numbers help produce the answer.

This comparison shows the effect of changing the input. It does not identify which attention head caused the answer.

Optional: see the attention connections (Head View)

Look inside: how attention mixes information

This is an optional view of an internal calculation, not an explanation of the model’s answer above. It shows the raw text you inspected in experiment 1. The meaning experiment includes a question and chat formatting, so its input is different.

How to read this picture

  • Left column: choose the token whose update you want to inspect.
  • Right column: positions it can draw information from. Stronger lines mean larger attention weights.
  • Layer: a processing round. Later rounds work with numbers already updated by earlier rounds.
  • Head: one of several attention calculations within a round. Each makes its own set of connections; their results are combined.

Why might “bank” point to itself? Its numbers may already carry information from earlier layers. The label still says “bank”, but the numbers behind it can change. A self-connection does not mean the context was ignored.

Heads do not have assigned jobs such as “understand rivers”. A single head may show a pattern that is difficult to interpret. You do not need to find a particular line to complete this lab.

FROM TOKENS TO NUMBERS

The numbers behind the tokens

Training learned a vector for each token ID. Coordinates work together; a negative value is not “bad” and a single coordinate rarely names a concept. The same token starts with the same embedding even when its context changes.

Try it: inspect “The river bank” and select its last token. Then inspect “The money bank”. Compare the starting embedding with the updated vector. If the tokenizer gives the same token ID to the final piece, its learned embedding stays the same; context can change the updated vector.

These are the first eight coordinates, not the whole vector or a projection. Qwen applies rotary position information to attention queries and keys; it does not simply add a position vector to the token embedding.

03 / INSIDE THE TRANSFORMER

Inside a transformer block

Each decoder block normalizes a token’s vector, mixes context through attention, adds that update, then applies a feed-forward network (MLP) and adds another update. Qwen repeats this process across its layers. Click a stage to inspect the selected token’s measured coordinates.

Inspect a sentence in lesson 1 to begin.

The strips show only eight coordinates. Intermediate values are captured from the actual Qwen forward pass. The final block also has a final normalization before output scoring.

Optional: Q, K, V and position

Learned projections form query, key and value vectors. Qwen normalizes queries and keys and applies rotary position information. Query–key comparisons, scaled by the square root of the head dimension, become attention weights through softmax. These weights mix values. Multiple query heads share key/value heads in Qwen’s grouped-query attention.

Experiment: change a parameter, keep the text fixed

This changes one entry in the selected layer’s query projection for one experimental pass. It is not training: no dataset, loss, or optimizer is involved. The trained weight is restored immediately afterward. Later generation uses the original model.

Try a different layer. One changed weight may have a very small effect; that is a valid observation.

Run a temperature experiment with 100 draws

Temperature and repeated draws

Temperature divides output scores before softmax. A lower temperature concentrates probability; a higher temperature spreads it. Neither guarantees factual accuracy. Compare the same logits at 0.3, 1 and 2. Each column also shows 100 independent samples from the complete vocabulary.

What if the model loses the beginning of the sentence?

A shorter context

A model can only use the context it receives. Keep the final tokens, remove earlier ones, and compare next-token predictions. This is a deliberate classroom truncation experiment, not Qwen’s native context limit. The removed text is genuinely excluded from the new forward pass.

What changes in this activity?

The trained model has learned patterns from examples. It uses the same broad process—represent text with numbers, use context, and predict the next piece—but on a much larger scale. This activity shows its real output probabilities. The earlier lessons inspect its internals; this activity adds chat formatting and continuation instructions.

Optional: where do these percentages come from?

The local backend computes full-vocabulary softmax from Qwen’s output scores. Sampling divides those scores by temperature first. Greedy selection chooses the highest score and displays temperature-1 probabilities. Instructions and chat-message boundaries are part of the model’s input context.

Instructions and what to look for

What is a chat’s context?

A chat request includes your latest message, prior messages, and instructions. The model then generates its reply one output token at a time. For a fair comparison, all four styles below receive the same conversation history and latest user message. Only the writing instruction differs. A full reply makes style easier to recognize than one token does.

The first output token has shared conversation context across styles. After that, each reply follows its own generated prefix. A later token’s probability therefore describes that particular reply’s path; it is not a controlled cross-style comparison. A token probability measures likelihood, not truth, quality, or membership in a genre.
