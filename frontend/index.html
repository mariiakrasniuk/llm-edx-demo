AI101 / A GUIDED INTERACTIVE LAB

How LLMs work?

You ask a question. A reply appears. How does a computer produce those words?

In this lab, you will explore the process behind tools such as ChatGPT: how text becomes numbers, how earlier text affects a reply, and how the model chooses what comes next. No programming or mathematics background is needed.

First, what is a large language model?

A large language model, or LLM, is a computer model trained on large amounts of text to learn patterns in language. Given some text, it calculates which small pieces of text could come next. Repeating that step lets it generate a sentence, an explanation, or a longer reply.

“Large” refers to the scale of the model and its training. The model has many adjustable numerical settings, called parameters. During training, those settings are adjusted using examples. They help the model capture patterns such as how sentences are formed and which ideas tend to appear together.

A familiar example: ChatGPT

When you use ChatGPT, you are interacting with a large language model through a chat application. ChatGPT is the application; the LLM powering it generates the reply.

You: Explain photosynthesis in one sentence.

An example reply: Photosynthesis is how plants use sunlight to turn water and carbon dioxide into sugars, releasing oxygen.

The reply appears as a sentence, but the model produces it one small piece at a time. These pieces are called tokens. A token can be a word, part of a word, or punctuation. A likely continuation is not automatically a true statement: the model can produce convincing mistakes.

Where do transformers fit in?

A transformer is the design used by many modern LLMs to process text. Think of the LLM as the trained model and the transformer as the way its calculations are organized.

First, the model represents tokens as lists of numbers, called vectors. Then it updates those lists using the surrounding text. A mechanism called attention mixes information from the available tokens. Another processing step works on each updated list. Together, these steps help produce the chances for the next token.

Your text → Tokens → Lists of numbers → Use context and update → Next-token chances

The model chooses one token, adds it to the text, and repeats. The earlier text, your instructions, and the reply so far form its context. As that context grows, the next-token chances can change.

Training and replying are different stages

Training: examples are used to adjust the model’s parameters.

Generating a reply: the model uses those parameters with the current context. In this lab, typing a new prompt changes the input; it does not retrain the model.

What will you investigate?

You will split text into tokens, follow their numbers through a small transformer, and see how context and temperature affect next-token chances. Then you will compare writing styles and chat with a trained model.

Text is split into pieces called tokens.

A token can be a whole word, part of a word, or punctuation. Different texts can have the same number of words but different numbers of tokens.

Why split text into pieces?

The model works with a fixed collection of text pieces, called its vocabulary. A tokenizer finds which pieces represent your text. Common words may fit in one piece; other words need several. These pieces do not have to match syllables.

Each token starts as a list of numbers.
This list is called a vector. It is the form of the token that the transformer can calculate with.


What do the numbers mean?
The model looks up a starting vector for each token. In a trained model, these values are learned from examples. There is not usually one number for “river,” another for “money,” or a number that measures how important the word is. The numbers work together.
Our example uses four numbers so that you can see the complete list. The model also adds information about position: where the token occurs matters. The same token can start with the same lookup values but be used in a different position or context.

What happens inside a transformer block?
A block is one round of two updates. Large transformers repeat many rounds.
  1. Use context — attention. Mix information from this token and earlier tokens into its list of numbers.
  2. Process the updated list — the feed-forward step. Apply another rule to the numbers at each position. This step is also called an MLP; it does not directly mix different token positions.
In both steps, the model keeps the previous numbers and adds an update. This keep-and-add connection is called a residual connection. The diagram below includes those additions in its updated lists.

Optional: the block’s mathematical steps
This is a simplified pre-normalized decoder block: layer normalization → causal attention → residual addition → layer normalization → MLP → residual addition. Layer normalization centers and rescales numbers before each update. A final normalization is applied before output scoring.

04
Use the surrounding text: attention.
The starting token is only part of the input. Attention mixes information from the available context into its numbers.


Why does context matter?
Think about the word “bank” beside “river” and beside “money.” A trained model can give the same token different updated representations in those contexts. It does not need to change its learned settings each time it sees the word.
Attention calculates how much to include from the information at each available position. The purple lines below show those proportions. A thicker line means a larger contribution to this update, not a probability that the next word will be correct.

Optional: how the attention proportions are calculated
Different matrices make three versions of each input list: a query (Q), a key (K), and a value (V). Comparing a query with available keys gives scores. Softmax converts the scores into proportions that sum to one. Those proportions mix the value vectors. The result is projected and added to the earlier representation. Later positions are excluded by a causal mask.
Attention = softmax(QKᵀ / √4) V
Optional: inspect the processing step and all calculations
The processing step is a feed-forward network, or MLP. Here it expands four numbers to eight, applies a nonlinear rule called GELU, and returns four numbers. It processes each position separately. Another residual connection adds this update to the previous numbers.


05
Choose one piece, then do it again.
The model uses the updated numbers at the final position to give each possible next token a chance. This list of chances is a probability distribution.


What does a percentage mean?
If a token has a 30% chance, imagine choosing the next token repeatedly with exactly the same input and settings. That token would be selected about 30 times out of 100 draws on average. It does not mean the token is 30% correct.
The model can always choose the largest chance, or it can sample: choose randomly according to the chances. After a choice, the new token becomes part of the input. The model calculates a new distribution for the following token.


Try this
  1. Read the eight candidate tokens and their chances. Together they add up to 100% in this small model.
  2. Click Choose most likely. Look at “Current input” and the new chances. The extra token has changed the context.
  3. Click Undo token, then Sample next token. A token with a smaller chance can still be selected. Repeat to build a longer sequence.
  4. Move Choice spread left to favor a narrower set of choices, or right to spread chances more widely. This control is commonly called temperature.
The idea: choose → append → calculate new chances → repeat. This small, untrained model shows the process but will not write sensible sentences.

05a
Same text. Different temperatures.
Temperature changes how the model’s scores become chances. It does not change the text, the learned settings, or the attention pattern.
What should you expect?
A lower temperature gives the higher-scoring pieces a larger share of the chances. A higher temperature spreads those chances more evenly. It does not add knowledge or guarantee creativity, accuracy, or a particular writing style.
At a temperature of zero, generation usually chooses a highest-scoring token instead of sampling. The three positive temperatures below all allow sampling.

  2. Click Draw 100 times. Each draw chooses a next token from the same unchanged text. The counts show how often each candidate was picked.
  3. Repeat. Counts get closer to the listed chances over many draws, but they need not match them exactly. This is repeated sampling, not a growing sentence.

05b
The model can only use what fits in its context.
A context window is the maximum number of tokens a model can handle in one request. It is measured in tokens, not words or pages.
What is inside the window?
Instructions, previous messages, your current text, and the generated reply use space. In a typical text-generation request, the input and output must fit within the model’s total context limit. A long reply needs room too.
Text outside the supplied context cannot be used directly by attention. An application may shorten a conversation, keep a summary, or retrieve relevant passages before sending it. A model does not automatically remember everything you have ever written.
A context window and an attention mask are different limits. The window limits how many tokens fit in the request. The mask prevents a position from using later tokens, even when those tokens fit in the window.
Try this
  1. Load the example, then shorten the demonstration window with the slider.
  2. Faded pieces are left out. Compare the next-token chances using the whole phrase with the chances using only the kept pieces.
  3. Restore the full window. The original chances return because the input is restored.
The idea: removing earlier text can change predictions. More available text does not guarantee the model will use every detail well.
A deliberately tiny window
This demonstration keeps the last few tokens and recalculates with the teaching model. It is not the connected API model’s context limit or an automatic truncation policy. The lab’s separate 32-token teaching limit keeps calculations inspectable.

Context includes the instructions and earlier text, not just the last visible words. Those inputs affect the hidden representations used to score the next token. Talk to the model in different styles.
See how small token choices become different complete replies.


What is a chat’s context?
A chat request includes your latest message, prior messages, and instructions. The model then generates its reply one output token at a time. For a fair comparison, all four styles below receive the same conversation history and latest user message. Only the writing instruction differs. A full reply makes style easier to recognize than one token does.
The first output token has shared conversation context across styles. After that, each reply follows its own generated prefix. A later token’s probability therefore describes that particular reply’s path; it is not a controlled cross-style comparison. A token probability measures likelihood, not truth, quality, or membership in a genre.


Use the experiment
  1. Ask a descriptive question and click Send to all four styles. Read the prose before looking at the numbers.
  2. Use the first-token table to compare matching candidates under the shared history. Similar first tokens do not mean the full replies will sound the same.
  3. Open Inspect generated tokens under a reply, then click a token chip to see its probability, alternatives, and preceding output context. Notice word fragments and punctuation again.
  4. Click Continue with this reply to keep one user–assistant exchange. Then ask a follow-up: all four styles receive that same chosen history. Without choosing a reply, the exchange is not committed; another send compares a fresh draft from the previously chosen history.

Two experiments. Two different changes.
Moving the model-setting slider changes a rule inside the teaching model. Changing the prompt, a style instruction, or the generated prefix changes context. Training updates parameters from data; the API experiments above keep the trained model fixed.
Can you explain the whole route?
Text becomes token IDs. IDs become vectors. Transformer blocks mix context and transform vectors. The final vector produces a next-token distribution. A selected token becomes part of the next input.
Compare your explanation
The token ID selects the same initial embedding, but the surrounding tokens can be different. Attention can mix different information into the token’s starting numbers, so the updated list can differ even though the starting lookup is the same. Position can also differ between sentences. The model’s parameters need not change.
